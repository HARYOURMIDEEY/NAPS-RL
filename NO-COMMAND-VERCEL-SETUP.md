# Vercel setup without using a terminal

This guide uses the Vercel website and GitHub website only. You still need to create accounts and paste provider credentials into Vercel; no one can safely do that on your behalf without access to your accounts.

## Before you start

- Upload this project to a private GitHub repository using GitHub's web interface (Add file → Upload files). Do not upload `.env`, `.env.local`, API keys, passwords, or `node_modules`.
- Import that repository into Vercel as a Next.js project.
- In Vercel, open **Storage / Marketplace** and add a Neon Postgres integration to this project. Let the integration create the database and add its variables.
- In Vercel Project → Settings → Environment Variables, set `DIRECT_URL` to the unpooled/direct Neon connection string (often exposed as `DATABASE_URL_UNPOOLED` or `POSTGRES_URL_NON_POOLING`; use the exact variable provided by your Neon integration). Keep `DATABASE_URL` as the pooled connection string. Do not paste these values into chat or commit them to GitHub.

## First deployment: database and Super Admin

Add these environment variables for the **Production** environment before deploying:

- `AUTO_DB_SETUP` = `true`
- `INITIAL_SUPER_ADMIN_PASSWORD` = a unique, strong password of at least 12 characters
- `AUTH_SECRET` = a long, random secret generated by a password manager
- `APP_URL` = your final `https://...vercel.app` URL (you can add it after the first deployment and redeploy)
- `EMAIL_SERVER` = SMTP connection URL from your email provider
- `EMAIL_FROM` = verified sender name and address from that provider
- `BLOB_READ_WRITE_TOKEN` = connect a Vercel Blob store to the project; Vercel can inject this variable automatically

The Vercel build script checks `AUTO_DB_SETUP`. When it is `true`, it runs Prisma schema sync and seeds the first Super Admin plus the starter courses. It does not use `--accept-data-loss`. Schema sync can fail if it would require a destructive change; review rather than forcing it.

After the first deployment succeeds:

1. Open Vercel → Settings → Environment Variables.
2. Remove `AUTO_DB_SETUP` (or set it to `false`).
3. Remove `INITIAL_SUPER_ADMIN_PASSWORD`.
4. Redeploy so those temporary setup settings are no longer active.
5. Log in at `/admin/login` with the configured Super Admin username and the initial password; change the password when prompted.

**Important:** Do not leave `AUTO_DB_SETUP=true` enabled for routine production releases. Prisma `db push` is for initial bootstrap/prototyping; future schema changes should use reviewed Prisma migrations.

## Email verification

Email verification codes are generated by the application, but sending them requires a working email provider. Configure `EMAIL_SERVER` and `EMAIL_FROM` using the provider's SMTP credentials and a verified sender. A Vercel URL alone does not send email. Test registration with an email address you control and confirm the six-digit code arrives before inviting students.

## Campaign banners

Connect a Vercel Blob store and verify `BLOB_READ_WRITE_TOKEN` exists in the Production environment. The Super Admin can then manage campaigns at `/admin/campaigns`; active campaigns display to eligible signed-in students.

## Verification status and launch gate

A successful Vercel build only verifies compilation. Before treating the portal as production-ready, manually test: registration and email code delivery; invalid/expired OTP handling; password reset; student/admin/Super Admin authorization; campaign create/pause/delete; image upload; level targeting; quiz/exam submission; and mobile layout. Check Vercel runtime logs after each test. Do not use real student records until these checks pass.

This package has not been certified by a live Vercel deployment or live email/database tests. Those require your Vercel project, database, email provider and credentials, which are intentionally not included in this source package.
